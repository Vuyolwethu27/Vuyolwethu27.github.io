
# Product Backlog – QR Code Attendance System

## Introduction
The Product Backlog contains a prioritised list of features and requirements for the QR Code Attendance System. It helps the development team organise the work needed to deliver the system.

## Product Goal
To develop a QR-code-based attendance system that improves attendance recording, monitoring, and reporting.

## Prioritised Product Backlog

| ID | Backlog Item | Priority | Status |
|---|---|---|---|
| PB01 | Student and Lecturer Login | High | Completed |
| PB02 | Generate QR Codes | High | Completed |
| PB03 | Scan QR Codes | High | Completed |
| PB04 | Record Attendance | High | Completed |
| PB05 | Prevent Duplicate Scans | High | Completed |
| PB06 | Track Punctuality and Attendance Status | Medium | Completed |
| PB07 | Display Real-Time Attendance Headcount | Medium | Completed |
| PB08 | Generate Attendance Reports | Medium | Completed |
| PB09 | Capture Device and Session Metadata | Medium | Completed |
| PB10 | Improve Dashboard User Interface | Low | Completed |

## Prioritisation
High-priority features support the core attendance process, including authentication, QR code generation, scanning, and recording attendance.

Medium-priority features improve attendance monitoring, reporting, and verification.

Low-priority features focus on further user interface improvements.
