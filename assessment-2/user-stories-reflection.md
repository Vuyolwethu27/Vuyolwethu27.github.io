
# Reflection on User Stories and Tasks

## Situation
During the QR Code Attendance System project, our team needed to identify and organise the system requirements so that the development work would meet the needs of its users.

## Task
My responsibility was to help clarify requirements and translate business needs into understandable user stories. I needed to consider what students, lecturers, and administrators would expect from the attendance system.

## Action
I examined the system requirements from different user perspectives and helped structure them using the user story format: As a user, I want a feature, so that I can achieve a particular goal. I also considered how each user story could be broken down into smaller development tasks.

## Result
This activity improved my understanding of requirements analysis and Agile planning. I learned how user stories help development teams focus on user needs and communicate the purpose of each feature. Breaking stories into tasks also helped me understand how requirements become actionable development work.

## Personal Learning
I learned that clearly written user stories can reduce misunderstandings and improve collaboration between team members. In future projects, I would aim to include clearer acceptance criteria and review user stories regularly with the team.
